# Lane 3: Revocation & Capability Enforcement Findings\n\n## Summary of Findings\n\n### 1. Critical Security Gap: Missing Revocation Check in Enforcement Pipeline\nThe 'Canonical 11-stage Enforcement Pipeline' (defined in `crates/fcp-core/src/enforcement.rs` and implemented in `crates/fcp-host/src/enforcement.rs`) includes a 'Revocation freshness' check, but this stage only validates the *age* of the revocation list. It does NOT actually check if the presented token, issuer key, or node attestation has been revoked via `RevocationRegistry::is_revoked()`.\n\n- **Impact**: Standalone hosts using the canonical pipeline for enforcement will accept revoked tokens as long as their revocation list is 'fresh'.\n- **Recommendation**: Expand `EnforcementContext` to include revocation status or the necessary IDs (`token_id`, `issuer_id`, etc.) and add a concrete revocation lookup to the pipeline.\n\n### 2. RevocationPush Handler Gap\nIn `crates/fcp-mesh/src/node.rs`, the `handle_gossip_message` function correctly identifies and verifies `GossipMessage::RevocationPush`, but this function is only called in tests and fuzzers. No production code path in `fcp-mesh` or `fcp-host` currently dispatches incoming gossip messages to this handler.\n\n- **Impact**: Real-time revocation updates pushed via gossip will be ignored by production nodes.\n- **Recommendation**: Ensure the mesh message router (likely in `fcp-host` or `fcp-mesh` transport layer) dispatches gossip messages to the `MeshNode` handler.\n\n### 3. Non-Monotonic Sequence Update in RevocationRegistry\nThe `RevocationRegistry::update_head` method in `crates/fcp-core/src/revocation.rs` does not verify that the new sequence number is greater than the current `head_seq`. It is a simple assignment.\n\n- **Impact**: A malicious peer or bug could 'roll back' the registry's sequence number, potentially causing `is_fresh` checks to pass for stale/revoked state if the caller doesn't enforce monotonicity externally.\n- **Recommendation**: Add a check in `update_head` to only apply updates if `seq > self.head_seq` (or `>=` depending on semantics).\n\n### 4. Duplicate Capability/Zone Implementations\nThere appears to be a parallel implementation of capability tokens and zone IDs in `crates/fwc/src/zone_scope.rs` that does not use the CWT-based `fcp-core` implementation. This may lead to inconsistent enforcement between the CLI/Standalone host and the Mesh-native host.\n\n---
